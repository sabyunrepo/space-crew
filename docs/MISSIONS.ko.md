# 50개 미션 규칙 기준 문서

2026-09-14 공유 엔진·로컬 데모·Node 실시간 서버에 1~50번을 적용했다. [최신 구현·검증 결과](./MISSION-IMPLEMENTATION-RESULTS.ko.md)와 [추가 판정 기록](./MISSION-RULINGS.ko.md)을 함께 읽는다. [2026-09-12 구현 대조](./MISSION-IMPLEMENTATION-AUDIT.ko.md)는 구현 전 조사 기록이다. 아래 표는 규칙 기준이며 테스트 근거는 최신 결과 문서에 별도로 기록한다.

최초 조사 2026-09-09, 전체 재확인 및 구현 참고 정리 2026-09-12. 항해일지 PDF의 미션 수록 면 전체(인쇄 pp.4–21, PDF pp.3–11)를 이미지로 렌더링해 본문과 토큰을 대조했다. 2026-09-14에 50개를 다시 대조했고 공유 엔진·Node 구현을 완료했다. 최신 출처 범위와 v3 수정 사항은 [원작 재대조](./ORIGINAL-MISSION-AUDIT.ko.md)를 따른다. 원작 이야기와 문장을 옮기지 않고 동작에 필요한 매개변수를 정리했다.

출처: [BGA에서 연결한 항해일지 사본](https://cdn.1j1ju.com/medias/dd/5a/3a-the-crew-the-quest-for-planet-nine-log-book.pdf). 제3자 호스팅 자료이며 공식 영문 번역본으로 인증된 자료라는 뜻은 아니다. 독일어 합본 교차 확인, 공식 규칙서, BGA 업데이트의 출처와 확인 범위는 [조사 근거](./MISSION-IMPLEMENTATION-AUDIT.ko.md#자료와-확인-수준)에 정리했다. 공식 한국어판의 용어 및 아래 미해결 판정은 추가 대조 대상이다.

## 구현 시 사용 순서

1. 이 문서의 해당 미션 행에서 목표 수·토큰·교신·특수 조건·5인 양도 여부를 확인한다. 범위는 3~5인 기본형이다.
2. [구현 대조 문서](./MISSION-IMPLEMENTATION-AUDIT.ko.md)의 상세 판정과 미확정 항목을 함께 읽는다. 현행 코드 지원 여부는 실행 데이터·엔진·테스트로 다시 확인한다.
3. 준비 절차, 공개 정보, 진행 상태, 성공·실패 조건, 종료 시점과 재접속 복원 방법을 정의한 뒤 구현한다.
4. 확인한 출처와 테스트 근거를 아래 구현 기록 형식으로 남기고, 검증된 범위에 맞춰 대조표와 활성화 상태를 갱신한다.

이 문서는 규칙 매개변수의 기준, 대조 문서는 상세 조사 근거 및 구현 상태의 기준이다. 두 문서의 중복 항목이 달라지면 출처와 변경 근거를 확인해 함께 수정한다.

## 읽는 방법

- `T`: 목표 카드 수. 0이면 별도 승리 조건을 사용한다.
- `O`: 절대 순번 토큰, `R`: 상대 순서 토큰, `Ω`: 마지막 목표 토큰.
- `D`: 정보 축소 통신, `C2/C3`: 해당 트릭부터 통신 허용.
- `결정/분배`: 지휘관 결정/분배 규칙. `X`: 아래 특수 조건.
- `★`: 5인 임무 양도 규칙 적용 대상.

순번은 카드 제출 순서나 트릭 번호와 다르다. 토큰 의미와 지휘관 절차는 [공식 규칙서 pp.14–19](https://www.thamesandkosmos.com/manuals/full/691868_Crew_Manual.pdf)를 따른다.

## 엔진에 반영할 해석과 검증 항목

아래는 원문을 재현한 규칙표가 아니라 위 조건을 프로그램으로 옮기기 위한 설계·테스트 항목이다.

| 검증 분야 | 구현 시 확인할 것 |
| --- | --- |
| 임무가 없는 미션 | `tasks.every(...)`가 빈 배열에서 참이라는 이유로 시작 즉시 성공시키지 않는다. 별도 성공 조건과 종료 시점을 둔다. |
| 절대/상대 순서 | 같은 트릭의 목표 집합을 일괄 평가한다. 렌더링 애니메이션 순서나 요청 도착 순서로 목표 획득 순서를 결정하지 않는다. |
| 첫·마지막 판정 | 인원별 실제 트릭 수를 계산한다. 3인 잔여 한 장을 가상의 추가 트릭으로 만들지 않는다. |
| 승리 카드와 포함 카드 | ‘이 카드로 승리’와 ‘이 카드가 포함된 트릭을 획득’을 다른 조건으로 구현한다. |
| 전체 지속 조건 | 마지막까지 유지해야 하는 조건과 목표 달성 즉시 끝나는 조건을 명시한다. 같은 제한 태그를 쓰는 16/17번도 종료 정책을 별도로 둔다. |
| 카드 이동 | 이동 전 손패 스냅샷을 기준으로 모든 이동을 함께 적용한다. 함수 재시도나 재접속으로 두 번 이동하지 않는다. |
| 토큰 편집 | 원래 배치를 저장하고 최종 확정 한 번만 허용한다. 교환 연산과 이동 연산의 입력 검증을 분리한다. |
| 지정 대원 선택 | 공식 영문판 기준으로 질문·응답·결정이 끝나기 전에 게임을 시작하지 않는다. 지휘관 결정·분배도 지휘관을 포함한 전원이 `예/아니오`로만 응답하며, 응답은 저장하고 새로고침 후에도 복원한다. 2019년 독일어판의 지휘관 결정 절차는 질문이 없어 판본 차이로 기록한다. |
| 통신 제약 | 카드 소유권·횟수·단계와 미션별 통신 허용 여부를 모두 검사한다. D를 ‘유일한 카드’로 저장하지 않는다. |
| 후반 미션 직접 시작 | 앞선 미션의 런타임 상태에 의존하지 않도록 모든 규칙을 개별 정의에 포함한다. |
| 5인 양도 | 앞선 24개 미션 완료 여부가 아니라 현재 미션 ID와 인원·양도 설정으로 적용한다. 토큰도 목표와 함께 이동한다. |
| 46번 준비 순서 | 구조 신호 결정/교환 이후의 소유권을 기준으로 대상과 공개 정보를 확정하는 BGA 동작을 대조한다. |

BGA 게임 페이지 업데이트에는 9·13·23·40·44·46번의 경계 처리와 새로고침 후 질문 응답 표시 수정이 기록되어 있다. 이 기록은 추가 테스트의 근거로 사용하며 전체 BGA 판정을 검증했다는 뜻은 아니다. [BGA 게임 페이지](https://ko.boardgamearena.com/gamepanel?game=thecrew).

## 추가 판정과 확인 수준

1. **12번의 이미 통신한 카드:** 저자와 논의했다는 답변의 중계를 근거로 추첨 후보에서 제외하고, 이동 뒤 기존 교신 표식은 유지한다(B). 출판사 정오표와 같은 수준의 공식 확인으로 표현하지 않는다. [관련 논의](https://boardgamegeek.com/thread/2482643/mission-12-and-revealed-cards)와 [판정 기록](./MISSION-RULINGS.ko.md)을 참고한다.
2. **준비 순서 결합:** 구조 신호는 공식 영문 규칙서에 따라 목표 배정 뒤, 첫 트릭·첫 교신 전에 실제 투표·교환을 진행한다. 브리핑에서는 방향 예약만 가능하다. 활성화 뒤에는 같은 미션의 재시도마다 교환 또는 생략할 수 있다. 역할 질문·토큰 편집·5인 양도가 겹치는 세부 순서는 ruleset별로 고정한다.
3. **2인 JARVIS/도전 변형:** 위 표는 3~5인 기본형 기준이다. 해당 변형의 공개 정보·판정 예외는 후속 범위다.
4. **한국어판 표현:** 지휘관·목표·통신 등의 용어와 판본 차이는 공식 한국어 자료를 확보해 대조한다.
5. **5·33·41번 담당자 선택 범위:** v3은 직접 확인한 항해일지에 따라 세 미션 모두 지휘관을 포함한다. v2의 5·33번 제외는 기존 시도에만 유지한다. 공식 한국어판 실물 문구는 추가 확인 대상이며 [판정 기록](./MISSION-RULINGS.ko.md)의 판본 차이를 보존한다.
6. **종료 시점:** 16번은 마지막 실제 트릭까지 진행한다. 17번은 일반 9가 승리하지 않은 상태에서 두 목표를 완료하면 즉시 성공한다. 원문에 없는 일반 9 전부 소진 조건은 v3에서 제거했다.

이 미해결 항목이 있다는 이유로 미션별 목표 수와 토큰 대조가 미완료인 것은 아니다. 반대로 표 작성만으로 엔진의 모든 예외가 검증되었다고 보고하지 않는다. 구현에서는 각 미션에 `source_reviewed`, `rulings_resolved`, `engine_tested`, `multiplayer_tested` 상태를 별도로 둔다.

2026-09-14 갱신: 위 추가 확인 항목의 현재 적용 판정은 [판정 기록](./MISSION-RULINGS.ko.md)이 우선한다. 12번은 저자와 논의했다는 답변의 중계에 근거해 교신 카드를 추첨에서 보호한다. 5·33·41번 선택 범위와 16·17번 종료 정책은 근거 수준과 구현 정책을 분리해 기록했다. 준비 절차 조합과 구조 신호는 공유 엔진 및 저장·복원 테스트로 검증한다.

## 구현 기록 형식

미션 구현·수정 시 아래 형식으로 이 문서에 기록을 추가하거나, 별도 검증 문서를 작성해 여기에서 연결한다. 다음 항목은 **문서 기록 규약**이며 현재 API에 해당 필드가 존재한다는 뜻은 아니다.

| 항목 | 기록할 내용 |
| --- | --- |
| 미션 / 확인일 / 적용 범위 | 번호, 날짜, 판본·ruleset, 인원과 선택 규칙 |
| `source_reviewed` | 확인한 목표 수·토큰·조건 및 출처 URL·면수 |
| `rulings_resolved` | 미확정 판정의 해소 여부, 근거 또는 사용자 지정 규칙; 해당 없으면 그 이유 |
| `engine_tested` | 성공·실패·경계 조건별 테스트 파일/사례와 실행 결과 |
| `multiplayer_tested` | 실제 확인한 인원·환경, 준비/진행 단계의 재접속, 공개 정보, 지정 번호·랜덤·재시도 결과 |
| 활성화 / 잔여 항목 | 활성 여부와 근거, 미검증 인원·선택 규칙·남은 작업 |

미실행 항목은 ‘미검증’으로 기록한다. 2026-09-12 기준의 시작 명령 50개 대조와 기존 테스트 결과는 [조사 당시 검증 기록](./MISSION-IMPLEMENTATION-AUDIT.ko.md#이번-검증-결과)에 있다.
