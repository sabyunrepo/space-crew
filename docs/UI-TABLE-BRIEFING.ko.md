# 미션·좌석·교신 UI 변경 브리핑

확인일: 2026-09-11. 이번 작업은 상태 확인·화면 재현·변경안 정리이며 앱 코드는 수정하지 않았다.

## 현재 상태

최근 커밋은 `90a2358`이다. 이전 로컬 데모 이후 Node/WebSocket 서버(`server/`), 파일 기반 방 저장, 서버 전용 다인 E2E, `ServerService`가 추가됐다. 게임 화면도 `src/components/table/`로 분리됐으며 불가 카드 비활성화, 손패 고정 영역, 게임 방법 페이지가 있다. 이번에는 현재 소스와 로컬 mock 화면을 조사했다. 실제 운영 배포 상태나 서버 다인 동작을 새로 검증한 것은 아니다. README의 “서버 미구현” 설명은 현재 코드보다 오래됐다.

현재 미션 규칙 엔진은 여전히 `missions[].playable`로 제한된다. 이 UI 변경을 50개 미션 규칙 구현 완료와 혼동하지 않는다.

## 문제 재현

1440×900의 3·4인, 390×844의 4인 화면에서 임무 4의 목표를 배분하고 교신한 뒤 확인했다.

1. `MissionPanel.tsx`: `manualOpen` 기본값이 false이고 목표 목록을 `open && …`로 렌더링한다. 실제 플레이 단계에서 닫힌 상태의 `.target-list` 수는 0이다. 기본 표시만 바꾸는 것보다 접기 구조 자체를 핵심 정보에서 제거해야 한다.
2. `styles.css`: PC 미션 내용은 absolute 오버레이, 모바일은 화면 하단 fixed 오버레이(max-height 55dvh)다. 모바일에서 미션을 펼치면 손패·제출 영역을 덮는 것을 스크린샷으로 확인했다.
3. `TrickArea.tsx`: 나를 배열 마지막으로 정렬하지만, `.played-cards`는 flex 가로 나열이다. 3인/4인 슬롯의 y 좌표가 각각 모두 같았다. “나를 마지막”은 “내 자리를 화면 아래”로 만들지 못한다.
4. `PlayerPanel.tsx`: 대원은 PC 오른쪽 목록/모바일 위쪽 칩, 낸 카드는 중앙 줄에 따로 있다. 교신도 카드 이름+설명 글자로만 표시돼 소유자·행동·교신을 매번 다른 위치에서 읽어야 한다.

## Aside에서 확인한 BGA 자료

Aside 프로필 연결이 끊겨 있었으나 앱 실행 후 복구했고 실제 브라우저에서 아래 페이지와 이미지 링크를 읽었다. 로그인·게임 참가·다른 사용자 접촉은 하지 않았다.

- [BGA 공식 The Crew 게임 페이지](https://en.boardgamearena.com/gamepanel?game=thecrew)의 Images 세 장 확인. [교신 예시 이미지](https://x.boardgamearena.net/data/gamemedia/thecrew/display/2.jpg?h=1651658885)에는 분홍 9 위쪽, 노랑 6 가운데, 초록 2 아래쪽에 원형 토큰을 놓는 모습이 명확히 나온다.
- [BGA 도움말](https://en.doc.boardgamearena.com/Gamehelpthecrew)에서 위=해당 색 최고 / 가운데=유일 / 아래=최저의 의미 확인.
- [2020-11-08 BGA 플레이 소개](https://www.fjelfras.de/wordpress/blog/brettspiele/die-crew-in-board-game-arena/)에 실린 [실제 게임 스크린샷](https://www.fjelfras.de/wordpress/wp-content/uploads/2020/11/Die-Crew-Screenshot.jpg)을 Aside로 열어 확인했다. Mission 7 설명이 게임판에 직접 보이고, 네 모서리의 플레이어 영역에 목표 카드·교신 카드·토큰이 모여 있다. 중앙 낸 카드 영역도 별도로 구분된다.

이 게임 스크린샷은 2020년 자료이며 현재 로그인한 라이브 테이블 화면으로 주장하지 않는다. 정확한 동서남북 배치는 사용자 요구에 맞춘 제안이다. BGA의 확인된 정보 배치 원리를 참고하고 기존 캐릭터 카드 아트는 유지한다.

## 제안하는 변경

### 1. 미션은 상시 보이는 게임판 정보로

- 상단 공통 미션 영역: 미션 번호·핵심 승리 조건·교신 제한·진행률을 계속 표시한다.
- 담당 목표 카드: 해당 대원 자리의 고정 영역에 항상 보이게 둔다. 순서 토큰·완료 여부도 카드에 부착한다. 상단에는 같은 카드 목록을 중복 출력하지 않아 공간을 확보한다.
- 목표 배분 단계에는 미배정 목표를 중앙 선택 영역에 표시하고, 배정되면 담당자의 영역으로 이동한다.
- 이야기 전문·규칙 해설·지난 트릭만 별도 상세 보기를 허용한다. 플레이 판단에 필요한 조건과 목표는 상세 보기에 숨기지 않는다.
- 오버레이로 손패/트릭을 덮는 현재 미션 UI는 제거한다.

### 2. 인원에 따른 방향별 좌석

내 자리를 항상 아래에 두고, 서버의 `seat` 순서를 나를 기준으로 순환시킨다. 단순히 내 항목만 배열 끝으로 옮기지 않는다. 턴 변경·재접속에도 다른 대원 간 상대 순서를 유지한다.

| 인원 | 내 자리 | 나머지 자리 |
| --- | --- | --- |
| 3명 | 아래 | 왼쪽 위 / 오른쪽 위 |
| 4명 | 아래 | 왼쪽 / 위 / 오른쪽 |
| 5명 | 아래 | 왼쪽 아래 / 왼쪽 위 / 오른쪽 위 / 오른쪽 아래 |

각 자리에는 닉네임·사령관/현재 차례·남은 장수, 목표 카드, 교신 카드+토큰을 묶는다. 낸 카드는 그 자리에서 중앙 방향의 전용 슬롯으로 이동하고, 트릭을 가져간 대원의 방향으로 정리한다. 카드 텍스트는 읽기 쉬운 정방향을 우선하며 사람 위치를 따라 글자를 뒤집지 않는다. 대기실은 좌석 참가/준비 중심의 기존 목록을 유지해도 된다.

### 3. 교신은 카드 위 토큰으로

| 서버 marker | 화면의 토큰 위치 | 의미 |
| --- | --- | --- |
| highest | 카드 윗부분 | 이 색 중 가장 높은 카드 |
| only | 카드 가운데 | 이 색은 이 카드뿐 |
| lowest | 카드 아랫부분 | 이 색 중 가장 낮은 카드 |

- 교신 확정 후 해당 대원의 영역에 카드 앞면+원형 교신 토큰을 항상 노출한다.
- 기존 텍스트는 보조 라벨/접근성 설명으로 남기고, 주 표현을 카드와 토큰으로 바꾼다.
- 교신 선택 단계에서도 공개될 카드와 토큰 위치를 미리 보여 준다. 터치로 위치를 고르거나 접근성 버튼으로 같은 동작을 수행하고 확정한다. 드래그만 요구하지 않는다.
- 사용 전 / 교신 카드 공개 중 / 교신 카드 제출 완료를 구분한다. `played=true`이면 공개 자리의 카드를 치우고 사용 완료 상태를 남겨, 아직 손에 있는 카드로 오해하지 않게 한다.
- 공개 이후 손패가 바뀌어도 최고/최저 토큰 위치를 다시 계산해 바꾸지 않는다.
- 이후 통신불량(Dead Zone)을 구현할 때 “가운데=유일”로 단순 매핑하지 않는다. 정보가 가려진 중앙 토큰은 별도 공개 상태로 설계해야 한다.

### 4. 모바일은 같은 방향 구조를 유지

미션 상단 + 방향별 게임판 + 하단 손패의 세 영역으로 나눈다. 좁은 화면에서 다시 플레이어를 한 줄 목록으로 바꾸지 않는다. 작은 목표 카드에는 색·숫자·순서·담당자 식별이 우선이고 탭하면 원본 카드가 확대된다. 목표나 교신을 전혀 보이지 않게 접는 방식은 사용하지 않는다.

5인·다수 목표에서 공간이 부족하면 테이블 내부 공간과 카드 크기를 조절한다. 특정 소형 화면에서 모든 카드 원본을 크게 표시하면서 스크롤도 전혀 없게 하겠다는 약속은 하지 않는다. 핵심 조건/목표의 식별 가능성과 손패 조작 영역의 비가림을 우선한다.

## 구현 경계 및 순서

1. `MissionPanel`: 조건 상시 표시 + `TaskCard` 분리, 오버레이 제거.
2. `GameTable` / `TrickArea`: `SeatLayout`으로 위치 계산 통일.
3. `PlayerPanel`: 게임 중에는 대원별 `PlayerSeat`로 재구성. 목표·교신·낸 카드를 같은 playerId에 결합.
4. `CommunicationCard` / `CommunicationToken`: marker를 위치로 렌더링하고 선택 미리보기 추가.
5. 반응형 배치, 카드 이동/트릭 회수 애니메이션, reduced-motion 적용.
6. Aside 시각 검수 + Playwright의 독립 세션 3/4/5인 검증.

현재 snapshot에 seat, playerId, tasks.ownerId/order/status, communication.cardId/marker/played, trick.playerId가 있으므로 기본 시각화 변경에 새 DB 필드나 기본 API 변경은 필요하지 않을 것으로 판단한다. 후속 특수 미션 공개 상태는 별도 검토한다.

완료 기준: 미션 핵심 정보를 보기 위한 접기/펼치기 0회, 목표/교신 소유자를 위치로 식별, 3/4/5방향 배치 및 모든 시점의 좌석 순서 유지, 교신 토큰 세 위치 정확성, 카드 제출 후 교신 상태 갱신, 모바일에서 손패 제출 버튼 가림 없음. 기존 서버·프론트 E2E의 가로 슬롯/오버레이 전제는 새 동작에 맞춰 수정한다.
