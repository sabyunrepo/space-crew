# 전체 50개 미션 구현 대조 — 2026-09-12

> 이 문서는 구현 전 감사 기록이다. 2026-09-14 현재 1~50번 적용 상태는 [최신 구현 결과](./MISSION-IMPLEMENTATION-RESULTS.ko.md), 추가 규칙 판정은 [판정 기록](./MISSION-RULINGS.ko.md)을 따른다. 아래 미구현 표와 실행 결과는 당시 상태로 보존한다.

**2026-09-12 조사 당시 플레이 가능: 1~4번. 미구현·비활성: 5~50번, 총 46개.** 50개 설명을 조회하거나 시작 번호를 설정할 수 있다는 사실은 그 미션을 플레이할 수 있다는 뜻이 아니다. 랜덤 추첨 대상도 현재는 1~4번뿐이다.

이번 작업은 Aside를 통한 인터넷 조사, 항해일지의 50개 조건 재확인, 현재 코드·기존 테스트 대조다. 게임 코드나 활성화 여부는 변경하지 않았다. 범위는 **The Crew: The Quest for Planet Nine의 3~5인 기본형**이며, Deep Sea·추가 미션·2인 JARVIS·3인 도전 변형은 제외한다.

## 자료와 확인 수준

- [영문 항해일지 전체 PDF](https://cdn.1j1ju.com/medias/dd/5a/3a-the-crew-the-quest-for-planet-nine-log-book.pdf): 제3자 호스팅 자료. PDF 3~11쪽, 인쇄 4~21쪽의 미션 1~50을 이미지로 모두 읽고 목표 수·토큰·특수 조건을 대조했다. 공식 영문 번역본으로 인증된 자료라고 표현하지 않는다.
- [독일어 규칙서·항해일지 합본](https://www.ggnf.de/spielanleitungen/diecrew/diecrew.pdf): 제3자 호스팅의 2019년 독일어 판본, 총 44쪽. 특수 조건 본문을 추가 대조했고, 6~8번 토큰도 이미지로 교차 확인했다. 영문 자료의 pink는 이 판본에서 rot로 표기한다.
- [Thames & Kosmos 공식 규칙서](https://www.thamesandkosmos.com/manuals/full/691868_Crew_Manual.pdf): 순서 토큰, 교신 제한, 지휘관 결정·분배, 5인 양도 등 공통 규칙 근거. 규칙 설명용 그림을 해당 번호의 실제 미션 설정표로 대신 사용하지 않는다.
- [KOSMOS 공식 독일어 다운로드 페이지](https://fragkosmos.zendesk.com/hc/de/articles/8069483104412-Die-Crew-Reist-gemeinsam-zum-9-Planeten-Anleitung-Logbuch-DE-Art-Nr-691868): 연결된 Logbuch 첨부는 이번 확인 시 **1쪽, 미션 1~3만 포함**한다. 전체 50개를 확인한 근거로 쓰면 안 된다.
- [BGA 게임 페이지](https://en.boardgamearena.com/gamepanel?game=thecrew), [BGA 도움말](https://en.doc.boardgamearena.com/Gamehelpthecrew): Aside 브라우저에서 공개 도움말·업데이트 기록 확인. BGA의 전체 미션을 실제 플레이해 검증한 것은 아니다.

원작 이야기나 공식 번역문을 재현하지 않고, 구현에 필요한 조건을 자체 문장과 매개변수로 정리했다. 공식 한국어판 용어·판본 대조는 남아 있다.

- `O[1,2,…]`: 전체 목표 중 절대 완료 순번. `R[1,2,…]`: 화살표 토큰끼리의 상대 순서이며 다른 목표는 사이에 들어갈 수 있다.

## 현재 코드에서 확인한 공백

| 위치 | 확인 결과 | 의미 |
| --- | --- | --- |
| `shared/missions.json` | `playable: true`는 1~4만 | 5~50은 설명 데이터만 존재 |
| `src/game/engine.ts`의 `begin()` | 비활성 미션 시작 거부 | 실제 시작 불가 |
| `begin()`의 목표 생성 | 순번은 `missionId === 3`일 때만 부여 | 8·15번조차 켜기만 하면 순서가 누락됨 |
| `resolve()` | 목표 소유자·기존 숫자 순서만 판정 | 특수 승리 카드·승수·역할·Ω 판정 부재 |
| `briefing_ready` / `choose_task` | 모든 미션이 일반 목표 선택으로 이동 | 목표 0개 미션은 선택할 카드가 없어 정지할 수 있음 |
| `resolve()`의 `tasks.every(...)` | 빈 목록은 참 | 목표 0개를 강제로 플레이 상태로 보내면 첫 트릭에서 잘못 성공할 수 있음 |
| 순번 판정 | 작은 숫자 토큰이 남았는지만 검사 | 토큰 없는 목표를 숫자 1 목표보다 먼저 획득하는 경우까지 일반화하지 못함 |
| `communicate` / `project()` | 기본 최고·최저·유일만 지원 | D, C2/C3, 특정 대원 교신 금지 부재 |
| `shared/contracts.ts` | 준비 질문·담당자 지정·토큰 편집·양도·구조 신호 명령 없음 | API와 재접속용 상태부터 확장 필요 |
| `server/rooms.ts`, `src/services/mock.ts` | 동일한 게임 엔진 사용 | 실시간 서버 모드에서도 5~50 제한은 동일 |
| `start_mission` / `next_mission` | 랜덤은 playable 목록, 순차는 다음 번호의 playable 확인 | 랜덤 1~4 한정, 순차 4 성공 후 현재 가능한 캠페인 종료 |

목표 0개 및 부분 순번 문제는 **비활성 미션을 켰을 때 드러날 코드상 위험**이다. 현재 지원되는 미션 1~4에서 동일 문제가 재현된다고 주장하지 않는다.

## 구현 전에 명확히 할 판정

1. **11번:** 지휘관을 제외한 모두가 침묵하는 것이 아니다. 지휘관이 고른 다른 대원 **한 명**만 교신 불가다.
2. **20·27·37번과 24·32·36·43번:** 공식 영문판에서 전자는 목표를 숨긴 상태로 지휘관을 포함한 전원이 `예/아니오`로 응답한 뒤 지휘관 이외의 한 명에게 전부 맡긴다. 후자는 한 장씩 공개할 때마다 지휘관을 포함한 전원이 `예/아니오`로 새로 응답하고, 지휘관 자신도 목표를 받을 수 있다. `모름` 응답은 없다. 최종 목표 개수 차이는 최대 1이다. 이전 조사에서 응답자에 지휘관이 포함된다는 점을 명시하지 않은 것은 오기여서 2026-09-14 정정했다. 2019년 독일어 합본은 지휘관 결정에 질문이 없어 판본 차이로 남긴다.
3. **9·26번:** 일반 1이 들어 있는 트릭을 잡는 것과 일반 1이 승리 카드인 것은 다르다. 로켓 1도 제외한다.
4. **13·44번:** 로켓 네 장을 한 사람이 모으는 조건이 아니다. 각 로켓이 각각 승리 카드가 되어야 하므로, 두 로켓을 같은 트릭에 내면 낮은 로켓의 조건을 더는 달성할 수 없다. 44번은 네 번의 로켓 승리에 순서도 있다.
5. **23·40번:** 전자는 토큰 두 개의 교환, 후자는 한 개를 빈 목표로 이동이다. 선택하지 않고 진행·선택 취소·최종 확정을 구분한다.
6. **29·34번:** 종료 때만 균형을 맞추는 것이 아니라 매 트릭 뒤 승수 차이를 검사한다.
7. **46번:** 이 프로젝트에서는 원작 분홍색을 **검은색 타마마 카드**로 대응한다. 따라서 `black-9` 보유자의 왼쪽 대원이 `black-1`~`black-9`를 획득한다. 흰 로켓과 혼동하면 안 된다. 왼쪽은 화면 좌표가 아니라 논리적인 좌석 순서다.
8. **48·50번:** 실제 마지막 트릭은 기본형에서 3인 13번째, 4인 10번째, 5인 8번째다. 3인의 남은 한 장을 추가 트릭으로 처리하지 않는다.
9. **D의 UI:** 공식 규칙서는 토큰을 카드 옆에 뒤집어 두며, BGA 도움말은 중앙 표시로 구분 정보를 숨긴다. 어떤 표현을 채택하든 데이터와 화면에 ‘유일’로 기록하면 안 된다.

공통 규칙 근거: [공식 규칙서 인쇄 10, 14~19쪽](https://www.thamesandkosmos.com/manuals/full/691868_Crew_Manual.pdf). 특수 조건 근거: 위 영문 항해일지 및 독일어 합본의 해당 미션.

### BGA에서 확인된 보완 근거

Aside로 확인한 [게임 페이지의 Latest Update](https://en.boardgamearena.com/gamepanel?game=thecrew)에는 다음 수정 내용이 있다. 페이지 전체의 배포 번호를 각 수정의 발표일로 간주하지 않는다.

- 9번: 일반 1을 모두 사용하고도 해당 승리가 없으면 실패 처리.
- 13·44번: 대원들의 남은 카드 수가 같고 로켓 4 승리가 보장되는 경우의 조기 종료 처리.
- 23·40번: 토큰 선택 취소 수정. 40번 안내를 교환에서 이동으로 수정.
- 44번: 기본 2·3인에서 마지막 남는 카드가 로켓 4일 때 실패 처리.
- 46번: **구조 신호 사용 또는 거절 이후** 분홍 9 보유자를 알리도록 수정.
- 지휘관 분배의 예/아니오 응답을 새로고침 후에도 표시하도록 수정.

이는 경계 사례와 재접속 테스트의 근거다. 모든 조기 종료를 그대로 구현해야 한다는 뜻은 아니며, 먼저 표준 성공·실패 조건을 정확히 구현하면 된다.

### 아직 별도 확인이 필요한 부분

- **12번의 이미 교신한 카드:** 무작위 이동 후보 포함 여부와 표식 처리의 공식 명시적 판정은 이번 조사에서도 확정하지 못했다. [기존 BGG 질문](https://boardgamegeek.com/thread/2482643/mission-12-and-revealed-cards)을 공식 답변으로 간주하지 않는다. BGA 재현 또는 판권자의 추가 설명 확인이 필요하다.
- **준비 절차의 조합:** 공식 영문 규칙서에서 구조 신호는 목표 카드 배정 뒤, 첫 트릭·첫 교신 전에 요청하며 활성화 후 같은 미션의 재시도마다 교환하거나 생략할 수 있다. 진행 중 요청은 허용하지 않는다. 역할 응답·토큰 편집·5인 양도와의 상태 흐름 및 46번 공개 순서는 전수 검증 대상으로 남긴다.
- **5·33·41번 담당자 선택 범위:** 각 미션 본문과 ‘지휘관 결정’ 아이콘 규칙을 자동으로 동일시하지 않는다. 특히 지휘관 자신을 선택할 수 있는지와 불가능한 선택의 처리 방침을 테스트 명세에 고정해야 한다.
- **종료 정책:** 16번은 전체 실제 트릭 동안 9 승리 금지를 유지한다. 17번은 목표 완료와 일반 9의 안전한 소진을 모두 요구하지만, 3인은 13번째 실제 트릭 뒤 한 장이 미사용으로 남으므로 그 카드가 일반 9여도 실패시키지 않는다. 이전 조사에서 이 3인 잔여 예외를 빠뜨린 것은 오기여서 2026-09-14 정정했다.

## 진행 순서 제안

1. **규칙 데이터·API:** 정확한 토큰 종류와 배열, 교신 정책, 준비 단계, 종료 정책, 역할·진행 상태를 구조화한다. 상태는 서버에 저장하고 재접속 때 복원한다.
2. **기본 목표·순서·교신:** 10번을 먼저 검증하고, 절대·상대·Ω 및 교신 제한을 추가한다. 42·47번은 기본 획득 규칙을 재사용할 수 있지만 5인 양도도 함께 고려한다.
3. **대화형 준비:** 질문 응답, 담당자 지정, 지휘관 분배, 토큰 교환/이동, 5인 양도 및 공통 선택 규칙인 구조 신호를 구현한다.
4. **특수 판정:** 목표 없는 미션, 카드 이동, 승리 카드 조건, 승수 균형, 첫·마지막·구간 역할을 구현한다.
5. **미션별 개방:** 성공·실패·경계 조건, 3/4/5인, 중간 재접속, 지정 번호 시작, 랜덤 추첨을 검증한 미션만 `playable`로 연다.

구조 신호는 선택 규칙이며 모든 미션에서 이를 쓰지 않고 플레이할 수 있다. 다만 원작 기능을 갖춘 최종판에서는 카드 교환, 재시도 간 사용 기록, 성공 기록의 추가 시도 수 처리가 필요하다.
