# 캐릭터 선택과 플레이어 테이블

## 구현

- 방 생성·초대 입장 전에 15종 캐릭터 선택. 대기실에서 변경하면 준비 상태를 취소하며, 출발 이후에는 변경 불가.
- 요시는 사용자 요청에 따라 오리지널 **초록공룡**으로 변경. 도마뱀은 기존 명칭 **코모도** 유지. 눈은 눈 결정, 만은 해안을 품은 베이 캐릭터.
- 캐릭터 중복 선택 허용. 같은 캐릭터를 골라도 이름·좌석으로 대원을 구분.
- 각 대원의 윗줄: **캐릭터 카드 → 신호 카드 → 낸 카드**. 아랫줄: 해당 대원에게 배정된 미션 목표 카드와 순서·완료 표시.
- 실제 좌석 순서를 순환 배치하고, 본인은 항상 아래. 3인 삼각형, 4인 십자, 5인 오각형. 재접속·차례 변경으로 좌석을 재정렬하지 않음.
- 미션 번호·핵심 조건·진행 상태를 상단에 상시 표시. 목표 선택 중 미배정 목표는 상단에서 선택, 배정 후 소유자 아래에 표시.
- 교신은 카드와 토큰으로 표시: 최고=위, 유일=가운데, 최저=아래. 교신했던 카드가 플레이되면 공개 이미지를 제거하고 사용 완료 토큰을 유지.
- PC·모바일 모두 같은 정보 순서 사용. 화면에 남은 공간에 맞춰 카드 크기를 조절.

## API와 저장

`shared/contracts.ts`를 원본으로 OpenAPI와 Edge 공통 계약을 생성한다 (`npm run contracts`).

- `CreateRoom` / `JoinRoom`: `characterId?: CharacterId` 추가.
- `Snapshot.players[]`: `characterId?: CharacterId` 추가. 과거 저장 데이터에 없는 경우 UI는 수달로 표시.
- 방 명령: `{ "type": "set_character", "characterId": "green-dino" }`.
- 기존 명령 봉투의 commandId·expectedRevision·attemptId를 그대로 사용한다. 캐릭터 변경 권한은 토큰으로 확인한 본인에게만 있으며 lobby 단계에서만 허용한다. 준비 해제, revision 증가, 저장·구독 알림을 기존 명령 경로로 처리한다.
- Node/WebSocket 서버는 방 파일에 저장하며, 다른 접속자의 스냅샷과 재시작 후 복원에도 반영된다.
- Supabase 준비 마이그레이션: `20260911114343_player_characters.sql`. `crew_private.room_members.character_id`에 문자열 enum CHECK를 추가한다. 방별 선택이므로 전역 players 프로필에 저장하지 않는다. 기존 private 테이블 접근 권한과 RLS를 유지한다.
- Supabase 저장소 구현 시 생성·가입·명령 트랜잭션에 해당 필드를 연결해야 한다. 현재 Edge Function은 기존 계약 골격 상태이며 원격 DB에는 이번 마이그레이션을 적용하지 않았다.
- 캐릭터 ID는 인증·게임 능력과 무관한 공개 외형 정보이다. 손패 공개 범위는 그대로 본인만 유지한다.

## 2026-09-14 미션 브리핑·배정 모달

`MissionSetupModal.tsx`에서 미션 조건과 해당 단계의 조작에 초점을 맞춘다. **내 손패와 대원별 배정 현황은 모달에 복제하지 않고 기존 게임보드에 유지한다.** 배경 흐림을 제거하고 낮은 명암의 배경막을 사용한다.

- 브리핑: 미션 번호·시도·요약·모든 추가 조건, 명시적인 `임무 확인 완료`, 본인 확인 여부와 전체 확인 인원수.
- 목표 선택: 내 차례/대기 안내와 아직 배정되지 않은 목표 카드·순서 토큰. 선택한 목표는 서버 응답에 따라 기존 플레이어 자리 아래에 나타난다.
- 역할 지정·지휘관 결정/분배·토큰 편집·5인 양도: 기존 `PreparationPanel`을 모달 안에서 사용한다. 응답 및 배정 권한과 전원 응답 조건은 기존 snapshot/명령을 따른다.
- 구조 신호 투표·카드 교환은 게임보드의 기존 준비 영역에 유지한다. 손패 카드 선택 목록을 이 미션 모달에 추가하지 않는다.
- `테이블 보기` 또는 Escape는 모달만 닫는다. 확인·선택 명령을 전송하지 않는다. `임무 준비 열기`로 다시 열 수 있고, 준비 단계 변경이나 내 목표 선택 차례가 오면 자동으로 열린다. 다른 대원의 선택 차례가 이어지는 동안 닫은 모달을 반복해서 띄우지 않는다.
- 새로고침 후 서버의 현재 준비 단계로 다시 열리며, 이미 저장된 확인/응답은 유지한다. 모든 준비가 끝나면 모달을 제거하고 상시 미션 띠와 테이블에서 플레이한다.
- 네이티브 dialog로 키보드 포커스를 제한하고 단계 제목에 초기 포커스를 둔다. 닫으면 다시 열기 버튼으로 포커스를 돌린다. 오류 및 미확정 요청의 재전송도 모달에서 접근할 수 있다.
- PC 최대 640px, 모바일 화면 너비에서 16px을 뺀 폭을 사용하며 내용이 길면 모달 내부에서 스크롤한다.

관련 검증: `tests/e2e/mission-setup-modal.spec.ts`는 22번 조건 표시, 손패/배정 현황 미복제, 닫기로 확인되지 않음, 확인 후 재접속, 목표 선택·자기 차례 자동 열기·배정 완료 후 복귀를 PC/모바일에서 검사한다.

## 2026-09-14 중앙 트릭·화면 맞춤·기본 이름 (최신 배치)

이 절의 배치가 앞선 3열 플레이어 패널/문서 스크롤 설명을 대체한다.

- 대원 패널에는 캐릭터와 교신 카드만 두고 목표를 그 아래에 유지한다. 실제 낸 카드는 중앙 트릭으로 모으고 대원 이름·방향·선도 배지를 표시한다. 본인 패널과 중앙의 본인 카드는 왼쪽 아래에 배치한다. 논리적 좌석 및 순환 순서는 변경하지 않는다.
- 게임 중 화면은 100dvh를 사용한다. `TrickArea`는 ResizeObserver로 보드의 가용 높이와 실제 목표·이름 행 높이를 측정해 패널 카드 크기를 맞춘다. 중앙 트릭은 별도로 크기를 계산한다. 손패는 중앙 정렬하며 넓고 높은 화면에서 최대 156px까지 커진다. 낮은 화면에서는 조작부 여백을 줄인다. 미션 조건과 손패를 숨기거나 본문을 잘라서 스크롤을 없애지 않는다. 길어진 준비 절차는 기존 모달 내부 스크롤을 유지한다.
- 본문 스크롤 방지는 진행 화면에 적용한다. 캐릭터 목록이 있는 홈·입장·로비는 문서형 화면이다.
- 지휘관 준비 화면은 ‘1. 내 응답’과 ‘2. 담당자 선택’을 구분한다. 전원 응답 후 지휘관에게 결정 안내와 선택 포커스를 제공하며, 일반 목표는 확인 전에도 보드에 공개한다. `MissionTaskInfo`는 공개 snapshot의 목표 수·hiddenTaskCount만 사용한다.
- 생성/초대 입장 화면에서 캐릭터를 고르면 대원 이름 입력값이 해당 캐릭터 이름으로 바뀐다. 사용자가 이후 직접 별명을 입력할 수 있다. 기존 방의 플레이어 이름은 소급 변경하지 않는다.
- 표시 이름: green-dino→요시, snow→콜드, coral→코랄, bay→베이, tree→트리. 저장 ID를 유지해 기존 방과 호환된다. 콜드 새 이미지는 `public/characters/cold-v2.webp`; 요시 생성은 도구 안전 시스템이 거절해 기존 이미지를 유지한다. 생성 원본과 정확한 프롬프트는 `assets/characters/v2/GENERATION.md`를 참조한다.

검증 결과: PC/모바일 준비·지휘관·플레이·이름 입력 24개 통과, 최종 문구 줄바꿈 보정 후 캐릭터/테이블 10개 재검증 통과. 3/4/5인 × 10개 뷰포트(320×667부터 2560×1440, 요청한 2279×1456 포함)에서 페이지 스크롤, 패널 상호 겹침, 중앙 카드 영역 충돌, 손패 침범이 없고 손패 중심 오차 1px 이내임을 확인했다. 실제 Node 서버 독립 브라우저 3/4/5인 플레이 3개 통과: 초대 입장·재접속·결과 일치 및 제3자 화면의 중앙 카드 소유자/이미지 동기화를 검사했다. 서버 모드 프론트 빌드와 TypeScript 검사 통과. 화면 측정 결과는 `artifacts/qa/characters/seat-scaling.json`, 실제 카드 스크린샷은 `server-central-play.png` 및 `desktop/mobile-N-table.png`에 보관한다.

### 중앙 트릭 확대 및 제출 동선 보정

중앙 카드의 기존 88px 상한/보드 폭 3.6% 제한을 제거했다. `TrickArea`는 중앙 그룹의 실제 크기와 대원 패널의 경계를 비교해 겹치지 않는 카드 크기를 계산한다. 카드뿐 아니라 대원 이름·트릭 제목·대기 표시·간격도 함께 비례 확대된다. 4인에서 위쪽 대원 공간은 계속 확보한다. 2279×1456의 5인 검증 예에서 카드 폭 약 80→136px, 중앙 그룹 약 260×480→460×840px를 확인했다. 실제 크기는 미션 조건과 주변 패널 높이에 따라 달라진다.

본인 신호 카드가 교신 선택 모드의 단일 토글이다. 클릭하면 선택 모드로 진입하며 같은 위치의 문구/접근 가능한 이름이 `교신 취소`, aria-pressed=true로 바뀐다. 다시 클릭하면 선택을 지우고 일반 손패 모드로 돌아온다. 별도 손패 헤더의 취소 버튼은 제거했다. 모달 닫기/다른 카드 선택은 선택 모드를 유지하며, 전송 완료 후 신호는 기존처럼 표시 전용이 된다. 시작/취소만으로 서버 리비전이나 교신 사용 횟수는 바뀌지 않는다.

PC/모바일4개 교신 E2E에 시작→취소→재시작, 모달 닫은 후 토글 취소, 선택 해제, D 표식과 최종 전송 검증을 포함했다.
