## 4. 결정 사항 (사용자, 2026-09-21)

- **`crew.bsh00.com` 앞의 Cloudflare는 그대로 둔다.** Cloudflare를 우회해도 실시간 알림(Realtime)과 익명 로그인(Auth)은 여전히 `sb-spacecrew2.bsh00.com`을 통해 Cloudflare로 나가므로 그 부분은 해결되지 않는다. 새 Supabase 프로젝트는 플랫폼 코드가 DNS를 항상 Cloudflare 경유(proxied CNAME → 터널)로 만들고 서버에는 밖에서 들어오는 문이 SSH뿐이라, 직접 연결로 바꾸려면 플랫폼 기능 추가가 필요하다. Coolify 앱은 KT 방화벽 80/443 개방 + Traefik 인증서 자동 발급 설정 + 앱별 DNS-only 기록이 있으면 직접 연결할 수 있지만, KT 콘솔과 Cloudflare DNS를 바꿀 수단이 이 세션에는 없었다.
- **Edge Function `crew-api`는 재배포하지 않는다.** 되돌리기용 경로로만 남겨두며, 아직 `instanceof` 오류 판정 버그와 `Access-Control-Max-Age` 미설정 상태 그대로다.
- **Next.js는 도입하지 않는다.** 이미 있는 Node 서버에 API 처리만 얹는 방식이 변경 파일 수도 적고(§`COOLIFY-ARCHITECTURE-PLAN.ko.md` 3절), Cloudflare가 정적 파일을 이미 잘 캐시해 주므로 새 프레임워크로 옮겨서 얻는 이득이 근거로 확인되지 않았다.
- **실사용자가 아직 없어서 약 64초의 다운타임을 받아들였다.** 게임 공개 시점이 오면 이 전제를 다시 확인해야 한다.

## 8. 남은 일 / 받아들인 위험

- **AI 대원 자동 진행이 DB 저장소(Postgres)에는 구현돼 있지 않다.** 서버 파일 모드에서만 지원된다.
- 플랫폼 쪽 받아들인 위험(플랫폼 문서 §6에서 그대로 옮김): Supabase VM **자기 자신의 셸**에서는 DOCKER-USER 방화벽을 우회해 사설 DB 포트에 접속할 수 있다(원격 공격은 아님, 이미 셸이 있는 경우에만 해당). `log_statement=ddl`이라 비밀번호를 만드는 `ALTER ROLE` 문이 이론상 평문 로깅될 수 있다(재현은 못 함). `sbp_app_runtime`이 `_supabase`·`template1`에 연결 가능하다(하드닝 안 함). DB 문을 닫아도(un-approve) 롤 자체는 남는다. 비밀번호는 `JWT_SECRET`에서 계산돼서 독립적으로 교체할 수 없다.
- 플랫폼의 `startFixture()` 테스트 13개가 여전히 실패하고, `regressionHarness` 불변조건 2개에 대응 테스트가 없다(이번 브랜치가 만든 공백은 아니고, 그대로 이어받았다).
- 레거시 서버 모드 코드와 `/data` 볼륨이 아직 남아 있다. 완전히 뺄지는 안정된 뒤 사용자가 결정한다.
- 저장소 루트의 `output/` 폴더는 git이 추적하지 않고, 이번 작업으로 만든 것도 아니다. 손대지 않았다.

## 9. 확인하지 않은 것

- 다른 통신사·다른 지역에서 접속할 때 Cloudflare 진입 거점이 어디인지 (이 맥북은 LAX로 확인했다).
- 브라우저에서 사전 확인(CORS preflight)이 줄어든 실제 체감 이득. 이번 측정은 Node 스크립트 기준이라 브라우저에서 따로 재지 않았다.
- 새 `realtime.messages` 파티션이 생긴 뒤에도 `realtime.send`가 똑같이 성공하는지 (1회차만 확인했다).
- 호스트(Supabase VM) 재부팅을 거친 뒤에도 방화벽 유닛과 워커가 같은 동작을 하는지.
- 실제 사람 여러 명이 동시에 접속하는 부하(이번 측정은 스크립트로 순환한 익명 사용자 46명 기준이다).
