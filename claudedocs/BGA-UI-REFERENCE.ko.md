# BGA 게임 테이블·가이드 화면 참고 명세

Task 1 산출물. Task 3(게임 테이블 UI)·Task 4(`/guide` 페이지) 구현자는 이 문서만으로, 보드게임아레나(BGA)를 직접 보지 않고 레이아웃을 결정할 수 있어야 한다.

## 0. 배경과 원칙

현재 데모(`artifacts/qa/demo-4p-m1-desktop.png`, `demo-4p-m1-mobile.png`)는 세로로 긴 문서형 페이지다: 헤더 → 좌측 탑승 대원 목록 → 미션 설명 → 목표 카드 → 트릭 → 결과 배너 → 맨 아래 손패. 손패가 스크롤 아래에 있어 "게임 테이블"이 아니라 "미션 리포트"처럼 보인다. 이 문서는 BGA류 게임 테이블(상태 표시줄 + 고정 손패 + 상시 보이는 플레이어 패널)로 바꾸기 위한 배치 결정을 담는다.

BGA 자체는 로그인 없이 실제 게임 화면(테이블 뷰)에 접근할 수 없어, 이 문서의 근거는 (a) BGA 공식 도움말/게임 페이지 원문 확인, (b) BGA Studio의 일반 게임 인터페이스 설계 원칙 문서, (c) 2차 자료(리뷰·규칙 정리 사이트)로 구성했다. §7에 출처와 확인하지 못한 항목을 정리했다. `docs/RESEARCH.ko.md` §3의 방침(통신 예약은 명시적 단계, 미션 조건 상시 노출, 자동 응답은 초기 미사용, 카드 선선택 자동 제출은 후속 기능으로 유예, 온라인/자리비움과 탈퇴는 별개 상태, 카드 이력 열람은 별도 기능)을 그대로 계승한다.

| **MissionPanel** | 미션 번호/이름, 임무 목표 목록과 담당자, 진행 상태(0/1 등), 특수 조건 요약(순서 토큰 등) | StatusBar 바로 아래, PlayerPanel 열을 제외한 폭 전체를 쓰는 얇은 띠(72–96px): 미션명 + 목표 요약 1줄 + "자세히" 토글. 토글 시 목표 카드 목록이 같은 자리에서 아래로 펼쳐지며 TrickArea를 밀어내지 않고 겹쳐 표시(오버레이) | 얇은 띠는 데스크톱과 동일하되 전체 폭 사용(PlayerPanel이 위로 이동했으므로) | 기본은 숨김. StatusBar 옆 "임무 보기" 버튼 또는 화면 하단의 손잡이(핸들)로 여는 바텀시트. 열렸을 때만 화면을 덮고, 닫으면 트릭·손패 조작에 방해되지 않음 |
| **Hand(내 손패)** | 보유 카드, 선택 상태, 낼 수 없는 카드 비활성화, "선택한 카드 내기" 버튼, 카드 수 | 화면 최하단 고정, 높이 160–200px. 카드 겹침 배치(부채꼴 아님, 좌우 겹침)로 5장이든 14장이든 한 줄에 표시. 선택 시 해당 카드만 위로 들어올림 | 데스크톱과 동일, 카드 폭만 축소 | 최하단 고정, 높이 140–170px. 카드 겹침 폭을 손패 수에 따라 동적 계산(예: `overlap = max(0, (cardWidth*n - availableWidth) / (n-1))`)해 14장도 가로 스크롤 없이 표시. 확인 버튼은 손패 바로 위 얇은 줄에 항상 노출 |
| **로그(트릭 기록)** | 직전 트릭 결과, 지난 통신 내역 | TrickArea 하단 또는 PlayerPanel 하단에 "지난 트릭 확인" 링크(현재 데모의 패턴 유지) → 클릭 시 오버레이 패널 | 동일, 링크는 MissionPanel 띠 옆에 배치 | 상시 노출하지 않음. StatusBar의 보조 메뉴(⋯) 또는 MissionPanel 시트 안에 "지난 트릭" 탭으로 통합 |

**공통 원칙:** 어떤 뷰포트에서도 `document.documentElement.scrollWidth <= innerWidth`(가로 스크롤 없음)를 지키고, 게임 조작(차례 확인·카드 선택·제출)에 필요한 요소는 페이지를 세로로 스크롤하지 않고 한 화면에서 보인다. 로비·브리핑·결과 화면은 문서형 스크롤을 유지해도 되지만(정보량이 많고 조작 빈도가 낮음), 같은 색상·타이포·카드 스타일(현재 데모의 다크 배경 + 라임 그린 강조 + 카드 슈트별 테두리 색)을 그대로 쓴다.

## 2. 상호작용 규칙

- **카드 선택 → 확인 흐름:** 탭/클릭 시 해당 카드가 살짝 위로 들어올려지며 `selected` 표시, 다시 탭하면 해제. 제출은 별도의 "선택한 카드 내기" 버튼으로만 이뤄진다(선택 즉시 자동 제출 금지 — 오조작 방지, RESEARCH.ko.md §3 "카드 선선택 자동 제출은 후속 기능" 방침과 동일하게 데스크톱·모바일 모두 확인 버튼 요구).
- **내 차례 / 남의 차례:** StatusBar 문구로 구분("당신의 차례입니다" / "<닉네임> 대원의 차례입니다"). 현재 차례인 플레이어의 PlayerPanel 항목에 강조 테두리+애니메이션 없는 정적 링 표시. 내 차례가 아니면 손패 전체가 `card--waiting`(회색 아님, 선택만 비활성)로 처리되어 "지금은 낼 수 없다"와 "이 카드는 규칙 위반"을 시각적으로 구분한다.
- **낼 수 없는 카드:** `card--illegal` 클래스로 회색조(`grayscale`) + 어둡게 + `aria-disabled="true"` + `cursor:not-allowed`. 이유는 `title` 속성과 함께, 모바일에서는 탭 시 카드 아래 짧은 안내 텍스트(토스트 또는 카드 하단 라벨)로 노출한다(모바일은 hover가 없어 `title`만으로는 부족).
- **통신 토큰 표시:** 카드 이미지 위에 작은 오버레이 배지 3종 — 위쪽(최고) / 가운데(유일, Dead Zone) / 아래쪽(최저). 손패 카드와 PlayerPanel 요약 텍스트(예: "파랑1·최저·사용함") 양쪽에 표시해 현재 데모의 패턴을 유지한다. 로켓 카드는 교신 대상이 아니므로 배지 자체가 뜨지 않는다.
- **트릭 종료·승자 표시:** 마지막 카드가 제출되면 TrickArea 위에 승자 캡션("<닉네임> 대원 트릭 획득", 현재 데모 문구 유지)이 뜨고 0.4–0.6초의 카드 정리 트랜지션 후 다음 트릭으로 초기화한다. `prefers-reduced-motion`이면 트랜지션 없이 캡션만 표시한다.
- **지휘관 표시:** 로켓4 보유자에게 PlayerPanel·좌석 라벨 양쪽에 동일한 배지(별/왕관 아이콘 + "지휘관" 텍스트)를 붙인다. 임무 선택 단계에서는 지휘관이 먼저 고른다는 안내를 StatusBar에 명시한다.

## 6. `/guide` 게임 방법 페이지

BGA의 규칙 요약("Rules summary")은 개요 → 준비 → 임무 → 트릭 → 통신 → 구조 신호 → 추가 조건(Dead Zone·지휘관 결정 등) 순으로 "점점 복잡해지는" 구성을 쓴다(§7 출처 1). 이 사이트는 실제 미션이 1~4번만 플레이 가능하므로, 그 순서를 참고하되 우리 사이트의 플레이 흐름(방 만들기 → 초대 → 준비 → 미션 진행)을 마지막에 별도 절로 추가한다. 문장은 아래처럼 직접 작성한다(원문 번역·복제 아님).

1. **한눈에 보기** — "함께 미션을 완수하는 협력 카드 게임입니다. 손패는 나만 보이고, 목표를 정확히 맞힌 대원이 트릭을 가져와야 성공합니다." 3줄 이내 요약.
2. **목표** — 대원 전원이 팀으로 승패를 나눈다는 점, 목표 카드를 담당한 대원이 그 카드가 포함된 트릭을 얻어야 성공한다는 점(`shared/missions.json`의 `summary` 문구와 일치시킨다).
3. **카드 구성** — 4가지 색 카드 1~9(총 36장) + 로켓 카드 1~4(총 4장), 총 40장. 실제 카드 이미지(`public/cards/<suit>-<name>-<rank>.webp`)를 색상별로 나열.
4. **지휘관과 첫 트릭** — 로켓4를 받은 대원이 지휘관이며, 임무를 먼저 고르고 첫 트릭도 먼저 낸다(`docs/RESEARCH.ko.md` §2 근거).
5. **트릭 규칙** — 색 따르기(첫 카드와 같은 색이 있으면 반드시 그 색을 냄) → 로켓 우선(로켓은 항상 으뜸패, 로켓끼리는 숫자가 큰 쪽) → 승자 선(같은 색이면 가장 높은 숫자, 로켓이 있으면 가장 높은 로켓). 예시 그림 3개(색 따르기, 로켓 승리, 무로켓 동색 비교).
6. **임무 카드 고르기** — 미션이 요구하는 목표 수만큼 지휘관부터 시계 방향으로 돌아가며 하나씩 고른다. 순서 토큰이 붙은 미션(예: 미션 3)은 지정된 순서대로 목표를 완수해야 한다.
7. **교신** — 시도마다 각자 한 번, 임무 배분 후 트릭이 시작되기 전에 한다. 카드 한 장을 골라 "이 색에서 가장 높다/낮다/이것뿐이다" 중 하나만 알릴 수 있고, 공개한 카드는 계속 손에 남는다. 이후 손패가 바뀌어도 표시는 갱신되지 않는다.
8. **성공·실패** — 모든 목표가 정확한 담당자에게, 정해진 조건(순서 등)대로 돌아가면 성공. 목표가 다른 대원에게 넘어가거나 조건을 어기면 그 자리에서 실패하고 같은 미션을 다시 시도할 수 있다(현재 데모 문구 "다시, 함께 도전해요" 유지).
9. **이 사이트에서 하는 법** — 탐사 허브에서 "새 탐사 만들기" → 초대 링크를 대원들에게 공유 → 전원 "준비 완료" → 미션 브리핑 확인 → 임무 선택 → 교신(선택) → 카드 내기. 회색으로 흐려진 카드는 지금 낼 수 없는 카드라는 뜻이며, 이유는 카드를 눌러보면 나온다.
10. **미션 1~4 요약** — `shared/missions.json` 기준: 미션 1(목표 1개, 특수 조건 없음), 미션 2(목표 2개), 미션 3(목표 2개, 지정 순서로 완수), 미션 4(목표 3개). 각 항목은 목표 수와 특수 조건만 안내하고 정답을 알려주지 않는다.

**레이아웃:** 데스크톱은 좌측 고정 목차(위 10개 항목, 스크롤 시 현재 절 하이라이트) + 우측 본문. 모바일(360px 기준)은 상단에 접이식 목차(펼침 버튼) + 이후 본문 세로 스크롤, 가로 스크롤 없음. 각 절 제목에 앵커(`#overview`, `#tricks` 등)를 달아 목차 클릭 시 이동한다.

**확인하지 못한 항목:**

1. BGA 실제 게임 테이블(로그인 필요)에서 트릭 카드의 정확한 좌표·픽셀 크기·좌석 배치 애니메이션은 실측하지 못했다. 위 데스크톱/모바일 좌석 배치는 트릭 테이킹 게임의 통상적 관행(원형/사다리꼴, 나=하단 중앙)을 따른 설계 제안이다.
2. 낼 수 없는 카드에 대한 BGA 자체의 시각적 처리(회색조 여부 등)는 확인하지 못했다. 이 프로젝트는 `Global Constraints`에 명시된 자체 규칙(회색조+선택 불가+이유 안내)을 그대로 채택한다.
3. "Crew Zone" 관련 BGA 버그 리포트(`bug?id=95575`)는 로그인 벽에 막혀 원문을 확인하지 못했다.
4. 트릭 종료 애니메이션의 정확한 지속 시간·모션 곡선은 BGA 실측이 아니라 이 문서의 설계 제안값(0.4–0.6초)이다.
5. 한국어 BGA 도움말은 `docs/RESEARCH.ko.md`에서 이미 "문서가 존재하지 않음"으로 확인됐다 — 이번 조사에서도 재확인했으며, 용어(지휘관·트릭·임무·교신 등)는 자체 정의를 그대로 쓴다.
